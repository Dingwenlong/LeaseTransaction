# 校园个人物品租赁与交易系统 Spec

## Why
为校园用户提供便捷的个人物品租赁与交易平台，促进校园资源共享，降低学生生活成本。依托微信小程序的轻量特性和微信生态的社交关系链，解决校园场景的身份认证和交易信任问题，构建基于校园身份认证的可信交易环境。

## 选题背景与意义
随着我国高等教育规模持续扩大，在校大学生群体已突破4700万人，形成了庞大的消费市场和闲置物品存量。现有解决方案存在信息不对称、跨校区交易成本高、缺乏身份认证导致的信任缺失等问题。微信小程序作为无需安装、即用即走的轻应用形态，在大学生群体中渗透率极高，能够有效解决校园场景的身份认证和交易信任问题。

## What Changes
- 创建完整的校园物品租赁交易系统架构
- 微信小程序前端（用户端）
- Vue3 + TypeScript 后台管理系统
- Java 25 + Spring Boot 3.x 后端 API 服务
- Y2K 复古未来感风格主页模板
- 租赁与交易双模式融合业务逻辑
- 基于微信生态的身份认证与支付集成
- 信用免押与风险控制机制
- 高并发场景下的系统性能优化

## Impact
- 受影响规格：用户认证、物品管理、订单系统、支付集成、信用体系、数据统计
- 受影响代码：完整的前后端项目结构

## ADDED Requirements

### 用户端功能模块

#### Requirement: 用户管理模块
系统应提供微信授权登录、个人信息维护、实名认证与校园身份核验功能，通过对接学校教务系统或学生卡信息确保用户身份真实性。

#### Scenario: 校园身份核验
- **WHEN** 用户提交学号、院系、校区信息进行身份核验
- **THEN** 系统验证信息真实性并标记用户为已认证状态

#### Requirement: 物品管理模块
系统应支持闲置物品发布与编辑，包括物品图片上传、分类标签设置、租赁价格与押金设定、物品状态描述等功能，同时提供我的发布记录管理与物品上下架控制。

#### Scenario: 发布租赁物品
- **WHEN** 用户填写物品信息、设置租赁价格和押金并上传图片
- **THEN** 物品提交审核，审核通过后显示在列表中

#### Requirement: 浏览与搜索模块
系统应实现物品分类导航、关键词检索、多条件筛选（价格区间、物品类别、所在校区）、基于地理位置的附近物品推荐以及智能排序展示。

#### Scenario: 附近物品推荐
- **WHEN** 用户授权地理位置信息
- **THEN** 系统基于LBS定位推荐附近校区的物品

#### Requirement: 租赁交易模块（核心业务）
系统应支持租赁与购买双模式选择。租赁流程包括预约申请、租赁时间选择、押金支付、订单确认、物品交付确认、归还提醒、归还验收、押金退还等完整闭环。购买流程支持即时下单、在线支付、物流跟踪或线下自提、确认收货、评价反馈。

#### Scenario: 完成租赁闭环
- **WHEN** 用户完成物品归还并通过验收
- **THEN** 系统扣除租金后退还剩余押金，订单状态更新为已完成

#### Requirement: 订单管理模块
系统应提供进行中订单实时跟踪、历史订单查询、订单状态变更通知、纠纷申诉入口等功能。

#### Scenario: 订单状态变更通知
- **WHEN** 订单状态发生变更
- **THEN** 系统通过WebSocket推送实时消息通知用户

#### Requirement: 消息与社交模块
系统应集成实时通讯功能，支持买卖双方在线沟通、系统消息推送（订单提醒、到期通知、活动公告）、评价与信用体系展示。

#### Requirement: 个人中心模块
系统应整合我的钱包（余额、押金、收支明细）、收藏夹、信用积分、帮助与客服入口。

### 管理端功能模块

#### Requirement: 用户管理
系统应实现用户账号审核、权限分配、信用等级调整、违规行为处理。

#### Requirement: 物品审核模块
系统应负责发布物品信息合规性审查、敏感内容过滤、分类纠错。

#### Requirement: 订单监控模块
系统应提供全平台订单状态跟踪、异常订单预警、纠纷仲裁处理。

#### Requirement: 数据统计模块
系统应生成用户活跃度报表、物品流转率分析、热门类别统计、财务收支汇总等可视化数据。

#### Requirement: 系统配置模块
系统应支持轮播图管理、公告发布、分类字典维护、参数设置。

#### Requirement: Y2K 复古未来感主页
系统后台首页应采用 Y2K 复古未来风格设计。

#### Scenario: 首页展示
- **WHEN** 用户访问后台管理系统
- **THEN** 显示包含霓虹渐变 Hero、功能卡组、信息区、口号区、收尾 CTA 的 Y2K 风格主页

## 技术架构
- **客户端**：微信小程序原生框架（WXML/WXSS/JavaScript）+ Vant Weapp/WeUI
- **后台管理**：Vue 3 + TypeScript + TailwindCSS
- **后端**：Java 25 + Spring Boot 3.x + Spring Security + MyBatis-Plus
- **数据库**：MySQL 8.0+
- **缓存**：Redis
- **对象存储**：OSS或服务器本地存储
- **地图服务**：腾讯地图API
- **支付集成**：微信支付SDK
- **实时消息**：WebSocket

## 核心数据表设计
- 用户表（user）
- 物品信息表（item）
- 订单表（order）
- 租赁记录表（lease_record）
- 支付流水表（payment_record）
- 评价表（review）
- 消息记录表（message）
- 信用记录表（credit_record）

## 研究难点与解决方案
1. **租赁与交易双模式融合**：设计统一灵活的订单模型，支持两种业务特性
2. **微信生态身份认证与支付**：对接学校认证体系，严格遵循微信支付规则
3. **物品状态实时同步**：高效时间段占用检测算法，数据库并发控制
4. **信用免押与风险控制**：基于用户历史行为的信用评分模型，风险预警机制
5. **高并发性能优化**：索引优化、缓存防护、接口限流、CDN加速

## 视觉设计规范
### 色彩方案
- 主色调：electric cyan, magenta, acid green
- 背景色：deep navy/black
- 渐变色：cyan→magenta→violet
- 金属质感：metallic silvers

### 页面结构
1. **Hero 区域**：霓虹渐变背景，2-3 行大标题，副标题，主次 CTA 按钮
2. **功能/产品卡组**：3-6 个卡片，包含图标、标题、描述、标签、操作按钮
3. **信息区**：带霓虹强调线的斑马纹表格/列表
4. **引语/口号区**：居中加粗标语，像素/金属装饰
5. **收尾 CTA**：宽幅渐变栏，主要操作按钮
